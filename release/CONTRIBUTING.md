# Contributing to the standalone framework

CLI users and agents share the same operation API. Preserve both workflows,
source identifiers and provenance, exact saved evidence, independent metric
denominators and local-first behavior. Add tests for contracts, adapters, scoring
and recovery changes. Run `python tools/release_check.py test --require-extras`
with the live/reports extras and test-only pypdf installed.

Software contributions intentionally submitted for inclusion are under Apache
2.0 unless explicitly stated otherwise, as described in section 5 of
[LICENSE](../LICENSE). Contributors retain ownership; no copyright assignment or
separate contribution license agreement is required by this project. You must
have the rights to submit your contribution, including employer permission where
needed. Mark third-party material and preserve its original license/notices.

Question contributions have separate content licensing and review requirements;
do not assume they inherit Apache 2.0. Changes to the bundled demo require a
CC BY 4.0 rights basis. See [license scope](../LICENSING.md) and
[pack authoring](../docs/PACK_ACCESS.md). Do not upload private questions, model
responses, credentials or vulnerability details in issues or pull requests.
Potentially dangerous cybersecurity content needs appropriate expert review
before release; biosecurity needs stricter handling. No private submission
service is currently promised. Do not submit sensitive material to request review.

Licensing a contribution does not authorize an agent to commit, push or publish
on someone else's behalf. Follow the owner's explicit instructions.
